Role-based session + middleware routing

Add role and collegeId / companyId to the JWT session. Next.js middleware reads the role and routes to the correct layout group automatically.
// middleware.ts — role-aware routing export function middleware(request: NextRequest) { const token = await getToken({ req: request, secret: process.env.NEXTAUTH_SECRET }); if (!token) return NextResponse.redirect('/login'); const { pathname } = request.nextUrl; const role = token.role as 'STUDENT' | 'FACULTY' | 'RECRUITER'; // Guard faculty routes if (pathname.startsWith('/faculty') && role !== 'FACULTY') return NextResponse.redirect('/dashboard'); // Guard recruiter routes if (pathname.startsWith('/recruiter') && role !== 'RECRUITER') return NextResponse.redirect('/dashboard'); // Guard student routes from other roles if (pathname.startsWith('/sprint') && role !== 'STUDENT') return NextResponse.redirect(`/${role.toLowerCase()}/dashboard`); return NextResponse.next(); }
// auth.ts — extend session with role callbacks: { async jwt({ token, user }) { if (user) { token.role = user.role; // 'STUDENT' | 'FACULTY' | 'RECRUITER' token.collegeId = user.collegeId; // Faculty: linked college token.companyId = user.companyId; // Recruiter: verified company } return token; }, async session({ session, token }) { session.user.role = token.role; session.user.collegeId = token.collegeId; session.user.companyId = token.companyId; return session; } }

OpenClaw is an autonomous AI job-hunting agent built into SkillGraph. It reads the student's resume + skill profile, searches Indian job platforms, scores job matches, and auto-applies — all without the student having to do anything beyond initial setup.
How OpenClaw works — step by step

Agent Architecture

A Bull queue job runs per student. Each job cycles through 5 platforms, scores matches via GPT-4o, tailors the resume, fills forms via Playwright, and reports back to the dashboard.
1
Student configures the agent
Student sets: target roles (multiple), preferred cities (Bangalore / Hyderabad / Remote), experience level, minimum CTC band (₹LPA), blacklisted companies, and a "apply limit" (e.g. max 20 auto-applications per day). Stored in OpenClawConfig model.
2
Background worker triggers on schedule
Upstash QStash fires a daily cron at 7:00 AM IST. For each active OpenClaw config, a Bull job is queued: processOpenClawAgent(userId). The worker runs in a Next.js API route handler with a 5-minute execution budget.
3
Platform scraping — 5 Indian sources
Playwright headless browser scrapes: Naukri.com (primary), LinkedIn India, Internshala (for internships), Wellfound (startups), and Unstop (hackathons + roles). Each listing is stored in OpenClawListing with full JD text, company, CTC, location, and platform.
4
GPT-4o match scoring
For each listing, GPT-4o receives: student skill profile JSON + JD text. Returns a structured match object: matchScore (0–100), missingSkills[], matchingSkills[], applyRecommendation: boolean, tailoringNotes: string. Only jobs with matchScore > student's threshold (default 65) proceed to application.
5
Resume tailoring per JD
GPT-4o rewrites the student's resume summary, skills section, and project descriptions to align with the specific JD's language and keywords — while keeping all facts true. Generates a tailored PDF via react-pdf and stores it in Cloudinary for this application.
6
Automated form fill + submission
Playwright navigates to the apply page. It fills: name, email, phone, LinkedIn URL, portfolio URL, current CTC, expected CTC, notice period, cover letter (GPT-4o generated). Uploads the tailored resume PDF. Submits the form. Captures confirmation screenshot.
7
Application logged to dashboard
Result written to OpenClawApplication: platform, company, role, applied_at, match_score, resume_version_url, status (Applied / Failed / Skipped). Student sees a live feed on /openclaw page with all applications, match scores, and tailoring notes.
